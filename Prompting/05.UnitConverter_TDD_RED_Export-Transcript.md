**User**

왜 fail이 아냐?

---

**Cursor**

RED가 fail이 아닌 이유: **구현이 이미 있기 때문**.

| 모듈 | 상태 |
|:---|:---|
| `converter/constants.py` | 상수 정의됨 |
| `converter/commands.py` | Command 4개 구현됨 |
| `converter/skill.py` | `run_skill` 완료 |

```
테스트 작성 → 구현 없음/스켈레톤 → pytest FAILED  ← 진짜 RED
테스트 작성 → 구현 이미 있음   → pytest PASSED  ← 지금 상태
```

순서가 뒤집힌 상태. 스켈레톤으로 되돌리면 fail 재현 가능.

---

**User**

RED 단계에서 fail이 나와야 하는건 아냐?

---

**Cursor**

**맞음. 순수한 RED 단계에서는 fail이 나와야 함.**

TDD: RED(테스트·구현 없음→FAILED) → GREEN(최소 구현→PASSED) → REFACTOR

`/tdd-red`도 동일 전제: pass면 구현이 이미 들어간 것.

RED-3 tamper 테스트는 pytest 관점에서 pass — `AssertionError`가 **의도된 실패**이므로 테스트 자체는 성공(회귀 가드).

